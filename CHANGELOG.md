# Changelog

## 1.6.2

- Исправлен оставшийся визуальный развал редактора при включении «Проверки счётчика»: светлая область больше не может появляться под окном и выталкивать его вверх.
- Корень редактора больше не задаёт `height: 100%` для `.window-content`. Вместо этого он занимает только свободную область рамки ApplicationV2 через `flex: 1 1 0` и `height: auto`.
- Для рабочей области добавлен `contain: size layout paint`, поэтому изменение высоты раскрываемых полей остаётся внутренним layout панели и не участвует в расчёте размера внешнего окна.
- Схема данных остаётся v11; миграция не требуется.

## 1.6.1

- Исправлен визуальный развал редактора при нажатии «Проверка счётчика». Причиной был partial render нескольких ApplicationV2 parts после изменения checkbox: при пересчёте layout окно могло оставлять огромную пустую область под рабочей сеткой и сдвигаться вверх.
- Переключатель теперь локально меняет видимость обычного и условного перехода, отдельно сохраняет состояние маршрутизации через action queue и вообще не запускает render редактора.
- Корневая grid-область редактора дополнительно ограничена height: 100%, min-height: 0 и overflow: hidden, поэтому содержимое frame panel не может растянуть ApplicationV2-окно за его рабочую область.
- Добавлен regression-тест, запрещающий render при переключении «Проверки счётчика».

## 1.6.0

- Предзагрузка переведена с модели «вся сцена до старта» на ограниченное стартовое окно: стартовый кадр плюс два уровня ближайших потенциальных переходов, включая условные развилки и варианты выбора, максимум 12 кадров.
- После готовности стартового окна клиент сразу может участвовать в синхронном старте; остальные изображения сцены догружаются в фоне по одному запросу; nearby-прогрев ограничен двумя параллельными запросами, чтобы не занимать все сетевые слоты браузера перед критическим переходом.
- Дальнее аудио больше не прогревается всей сценой. Музыка, SFX и голоса загружаются для текущего и ближайших кадров, что убирает массовую загрузку длинных звуков в больших катсценах.
- Перед фактическим переходом модуль гарантирует готовность ассетов целевого кадра. Пока они загружаются, предыдущий кадр остаётся отображаться, поэтому не возникает пустого портрета или задника.
- После каждого перехода приоритетно прогревается ещё два уровня ближайших кадров; запросы одного и того же ассета дедуплицируются между стартовой, фоновой и приоритетной загрузкой.
- Фоновая предзагрузка прекращает планировать новые запросы после закрытия плеера.
- Исправлены гонки быстрых сетевых переходов: frame/text advances теперь проходят через одну playback-очередь, поэтому медленная предзагрузка старого перехода не может поверх нового кадра применить устаревшие эффекты, аудио или render.
- Ошибка фоновой загрузки ассета больше не кэшируется навсегда. При переходе в критический кадр ранее неудачный файл запрашивается снова, а при повторной временной ошибке выполняется ещё одна немедленная попытка.
- Стартовый и nearby preload больше не ждут все voice-файлы будущих кадров: до входа подготавливается только непосредственно нужный voice; остальные реплики текущего кадра прогреваются уже в фоне и дополнительно проверяются перед сменой текстового блока.
- `ready` теперь отправляется только после повторной проверки критических ассетов стартового кадра и завершения loading-render, что устраняет гонку между экраном загрузки и первым кадром.
- Сетевые advances, пришедшие во время первоначального старта или восстановления после reconnect, остаются в буфере до завершения восстановления; drain обрабатывает также сообщения, пришедшие во время самого drain.
- Распознавание preload-файлов расширено для AVIF и распространённых аудиоконтейнеров/кодеков (`oga`, `opus`, `aac`, `webm`).
- `VN: ожидание предзагрузки` теперь фактически относится к готовности стартового буфера клиентов. Схема данных остаётся v11; миграция не требуется.

## 1.5.0

- Любому кадру теперь можно назначить изменение счётчика: выбрать счётчик, операцию «добавить/отнять» и величину. Эффект срабатывает один раз при входе в кадр и доступен репликам, наррации и кадрам выбора.
- Эффект кадра применяется до проверки условного следующего кадра, поэтому изменение сразу учитывается его маршрутизацией.
- Переключатель «Проверка счётчика» больше не меняет скрытые поля и layout напрямую: состояние сохраняется через очередь редактора и панель аккуратно перерисовывается.
- Менеджер счётчиков учитывает эффекты кадров и очищает такие ссылки при удалении счётчика.
- В редакторе пресетов персонажей восстановлена вертикальная прокрутка длинного списка.
- Схема данных поднята до версии 11; старые кадры получают отключённый эффект счётчика без изменения поведения.
- Typewriter теперь считает Unicode-графемы, а не отдельные code points: cursed/zalgo-текст с комбинируемыми знаками снова анимируется как обычные видимые символы и не перескакивает ошибочно через лимит 900 символов.
- Исправлена синхронизация self-loop переходов: явный повторный вход в тот же кадр теперь передаётся отдельным флагом, поэтому удалённые клиенты повторно применяют эффект кадра, а обычная смена текстового блока в том же кадре эффект не переигрывает.

## 1.4.0

- В один кадр теперь можно добавить несколько персонажей одновременно через отдельный блок «Персонажи в кадре».
- Для каждого дополнительного персонажа независимо выбираются пресет, портрет, имя и позиция слева, по центру или справа.
- Для основного и каждого дополнительного персонажа можно отдельно включать и выключать отображение имени в обычной диалоговой панели; центральный текст по-прежнему скрывает имена.
- Дополнительные портреты предзагружаются вместе с остальными ассетами сцены и показываются одновременно с основным портретом. Выбор «Нет портрета» теперь корректно очищает портрет дополнительного персонажа.
- Основной портрет сохраняет прежнюю механику наследования между кадрами; дополнительные персонажи являются локальными для текущего кадра.
- Схема данных поднята до версии 10. Старые кадры автоматически получают пустой список дополнительных персонажей; прежнее отсутствие имени в центральном режиме сохраняется при миграции.

## 1.3.0

- Новые кадры и новые пресеты персонажей теперь используют левую позицию портрета по умолчанию.

- Добавлен режим виньетки на уровне кадра: «Авто», «По краям кадра», «Вокруг текста» и «Нет».
- В автоматическом режиме обычные сцены сохраняют полноэкранную виньетку, а центральный текст получает компактное затемнение непосредственно вокруг текста.
- Блок имени говорящего теперь соприкасается с верхней границей текстовой панели без зазора; при левом и правом расположении он выравнивается по соответствующему краю панели.
- Схема данных поднята до версии 9; старые кадры автоматически получают режим виньетки «Авто».

## 0.5.12

### Производительность

- Редактор строит единый индекс кадров, папок, счётчиков, целей переходов и ошибок на один render.
- Дерево кадров и список папок строятся через `Map<parentId, children>` вместо повторных полных сканирований.
- Хранилище кэширует санитизированный snapshot и отдельные индексы сцен, ассетов и персонажей.
- `getScene`, `getAsset` и `getCharacter` клонируют только запрошенную сущность.
- Preload обновляет прогресс напрямую в DOM не чаще одного раза за animation frame.
- Граф заранее индексирует последовательные переходы и DOM-рёбра, а при drag обновляет только связи перемещаемого узла.
- Typewriter использует один text node и `requestAnimationFrame` вместо пересборки всей строки через `setInterval`.
- Изменения громкости применяются сразу, а client settings записываются с debounce.

- Удалены межфайловые дубли селекторов и устаревшие override-слои 0.5.9–0.5.11.
- Из 67 `!important` оставлены только 9 технических правил fullscreen-плеера.
- Унифицированы кнопки, поля, focus-state, form-group, path-field, scrollbar и цветовые токены служебных окон.
- Добавлены системный reduced motion и client settings для отключения анимаций и мгновенного текста.
